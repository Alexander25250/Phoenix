# PHOENIX 0.8.0 — автообновление

## Что нового
- Проверка последнего GitHub Release.
- Если в релизе есть `PHOENIX-win-x64.zip`, программа предлагает установить обновление.
- Архив скачивается, приложение закрывается, PowerShell helper заменяет файлы и запускает PHOENIX снова.
- Обновление не удаляет другие файлы/папки в каталоге приложения; одноимённые файлы сборки заменяются.

## Важно: сначала подключить свой GitHub-репозиторий
Автообновление настроено на публичный репозиторий `Alexander25250/Phoenix`. Перед использованием проверь, что репозиторий Public и в нём опубликован GitHub Release.

## Как подготовить релиз
1. Убедись, что репозиторий `Alexander25250/Phoenix` имеет видимость Public.
2. Загрузи исходники проекта в репозиторий (не загружай `.venv`, `build` или `dist`).
3. Запусти `build_exe.bat`.
4. Запусти `make_release_zip.bat`.
5. Создай GitHub Release с тегом `v0.8.0` и загрузи `PHOENIX-win-x64.zip` в Assets.
6. Для каждой следующей версии увеличивай `APP_VERSION` в `main.py`, пересобирай программу и добавляй новый `PHOENIX-win-x64.zip` в новый Release.

Архив `PHOENIX-win-x64.zip` должен содержать файлы сборки в корне архива (например, `PHOENIX.exe` и `_internal/`), а не дополнительную внешнюю папку `PHOENIX`.

## Сборка
- `run.bat` — запуск из Python-среды.
- `build_exe.bat` — сборка EXE.
- `make_release_zip.bat` — подготовка ZIP для GitHub Releases.
- Для рабочего обновления запускай собранный `dist\PHOENIX\PHOENIX.exe`, не `main.py`.

## Ограничения
- Это обновление поверх существующей папки приложения, а не полноценный MSI-инсталлятор.
- Рекомендуется держать программу в постоянной папке, а не во временной папке распаковки.
- В данный момент нет цифровой подписи обновлений; используй только собственный доверенный GitHub-репозиторий.
